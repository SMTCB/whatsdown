How WhatsDown is built

This spec covers the architecture, agent graph, data model, integrations, model routing, security and delivery pipeline. Each section ends with the decision it depends on, so you can see what would change if that decision changed.

1. Architecture

Everything WhatsDown owns sits in the green zone. Agents reach external services only through the Inngest functions; the browser never calls them directly.

4. Durable execution

Vercel functions stop after a few minutes. A diagnosis can take longer, and a ticket can wait days at a gate. The graph therefore runs in slices:

  1. An event (ticket/created, ticket/gate1.decided, github/ci.completed…) triggers the Inngest function ticket/run.
  2. Each Inngest step.run calls graph.invoke(input, {configurable:{thread_id: ticketId}}) with a ~240 s budget. After a slice it calls graph.invoke(null, …) to continue from the last checkpoint.
  3. When the graph hits interrupt(), the function ends. Nothing runs or costs money while waiting.
  4. The resume event calls graph.invoke(new Command({resume: payload}), …).
  5. Inngest crons check for stuck tickets (no event in 24 h) and expire needs_info after 7 days.
Spike in Sprint 0

The slice-and-resume pattern is validated first (WD-5/WD-6). If it fails, the fallback is Vercel Cron every minute draining a jobs table, recorded in ADR-002.

7. Sandbox (E2B)

Read mode (Diagnostics)

Shallow clone at the default branch, npm ci, tools: list_files, read_file, search (ripgrep), git_log, run_tests (allowlisted scripts). No write tool exposed.

Write mode (Developer)

Adds write_file, apply_patch, run (lint, build, vitest only). Output is git diff, returned to the app, guarded, then pushed by the GitHub App.

  • Clone uses a read-only installation token that expires in 1 hour. No Supabase, Vercel or LLM keys enter the sandbox.
  • Network egress is limited to the npm registry and GitHub where E2B allows it.
  • Timeout 20 min per sandbox; killed after each node.

8. WhatsApp Cloud API

  • GET /api/webhooks/whatsapp answers Meta's verification challenge with WHATSAPP_VERIFY_TOKEN.
  • POST verifies X-Hub-Signature-256 with the app secret, stores the message, returns 200 within 5 s and hands off to Inngest (whatsapp/message.received).
  • A small conversation state machine (collecting → confirming → created) runs per reporter, using gpt-oss-20b to extract fields.
  • Media is downloaded via the Graph API into Storage. Audio is transcribed with whisper-large-v3-turbo on Groq.
  • Outbound: free-form text inside the 24 h window; otherwise the approved template ticket_update with parameters.

  • Router: lib/llm.call({task, ticketId, …}) picks the model from the project settings, logs llm_usage, and checks the ticket budget before every call.
  • Caching: the system prompt, tool definitions and the repo context files form a stable prefix with a cache breakpoint. Hits are verified via cache_read_input_tokens.
  • Budget: $1.50 per ticket by default. At 80% the owner is emailed; at 100% the node stops and the ticket goes to failed with reason budget.
  • Experiment (S6): run the replay benchmark with Sonnet 5.5 for Diagnostics/Developer and compare solve rate and cost with Opus 5.5.

13. Deploy pipeline

Local (npm run dev + inngest dev + supabase local)→ git push branch→ GitHub Actions CI→ Vercel preview→ You merge PR→ Vercel prod deploy
  • Migrations: written locally, tested with supabase db reset, applied to the hosted project by you with supabase db push.
  • Inngest: Vercel integration syncs functions on each deploy.
  • Preview deployments use the same Supabase project but with AGENTS_ENABLED=false to avoid duplicate runs.

15. Known limits

  • Vercel Hobby function time and Inngest free-tier step counts bound how long a slice can run and how many tickets per month fit.
  • Supabase free projects pause after a week without activity; a weekly Inngest cron pings the database.
  • The fantasy repo's full e2e suite (up to 60 min) runs only in its own CI, not in the sandbox.
  • Groq free-tier rate limits may trigger the Haiku fallback during bursts.
  • The WhatsApp test number can message only up to 5 verified recipients.
