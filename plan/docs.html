Documentation register

Every document WhatsDown produces. Some you write while building. Others the agents write automatically for every ticket. Each row says where the document lives, who writes it, when it first appears and what triggers an update.

📁 In the WhatsDown repo

Markdown under docs/, versioned with the code. Reviewed in PRs like any other change.

🗄️ In the database

Per-ticket reports from the agents, stored in the artifacts table and shown on the ticket page.

🔗 In the target repo

PR descriptions, PR comments and BACKLOG.md entries the bot writes on the fantasy repo.

Lifecycle of the per-ticket documents

For each ticket the agents write a short trail of documents, so you can always see what was decided and why:

Intake record→ Triage note→ Diagnosis report→ Gate 1 decision→ Change summary + PR→ QA report→ Merge record→ Reporter messages

Conventions

  • Format: Markdown for repo documents. Agent reports are stored as JSON (for machines) plus Markdown (for you).
  • ADRs: numbered ADR-NNN-short-title.md, using a context → decision → consequences template. Once accepted, an ADR is never edited; a new one supersedes it.
  • Prompts: one file per agent role. A front-matter version is bumped on every change, and each agent run records the version it used.
  • Ownership: "You" means you write or approve it. "Agent" means it's generated and shown read-only. "Auto" means a script or CI generates it.
