Build WhatsDown, one sprint at a time

WhatsDown is an AI maintenance crew for your hobby apps. Someone reports a problem by web form or WhatsApp. Agents triage it, find the cause, write a fix, check it, and tell the reporter. You approve the plan and merge the fix. The first app it looks after is the Forza Fantasy League (SMTCB/WCFantasyFootball).

9 sprints · ~1 week each Next.js + Supabase + Vercel LangGraph.js agents 2 human gates

The five documents

i

Implementation plan

The tech stack, how we'll work (agile, 1-week sprints), and each sprint's goal, stories, demo and exit criteria. Also covers the move from local development to GitHub and Vercel.

A kanban board of every backlog item. You can filter it by sprint. Click a card to see its acceptance criteria or move it to another column. Moves are remembered in your browser.

Every document the project produces: who or what writes it, where it lives, when it's created, and what triggers an update. Includes the reports the agents write for each ticket.

Functional specification

What the platform does, in plain language. Covers the actors, ticket lifecycle, web and WhatsApp intake, the five agents, the approval gates, notifications and admin screens.

 v

Technical specification

How it's built: architecture, agent graph, data model, integrations (GitHub App, E2B, WhatsApp Cloud API), model routing and costs, security, environments and testing.

Decisions already made

TopicDecision
PurposeA hobby and learning project. Build it, measure how well it works, iterate.
Approver & testerYou, alone, at first. League users join later through WhatsApp.
HostingVercel (app), Supabase (a new, separate project for the database), GitHub repo auto-deployed by Vercel.
Way of workingBuild locally first, push to GitHub at the end of Sprint 0, then deploy every merge to main through Vercel.
AgentsLangGraph.js. State is saved in Postgres, so a ticket can pause for days and pick up where it left off.
ModelsGroq's free models handle the light work: triage, messages, the injection screen and voice notes. Claude handles diagnosis and coding.
Code sandboxE2B. The agents never run code on Vercel or against your live database.
IntakeWeb form first (Sprint 1). WhatsApp Cloud API with a test number in Sprint 7.
NotificationsSent automatically. At first the only recipient is you.
BACKLOG.mdEvery agent PR on the fantasy repo also adds a 🟡 entry at the top of its BACKLOG.md, in the repo's own format. WhatsDown writes this entry from a template, not the AI model.

Open items to settle

Supabase project slots

The free plan allows two active projects, and the fantasy app already uses one. WhatsDown takes the second, so a third hobby app would need a paid plan or a paused project.

Groq free-tier limits

The figures published on the docs page are for the Developer plan. Check your own free limits in the Groq console under Settings → Limits before Sprint 2.

When to hand over keys

Groq is needed in Sprint 2, Claude in Sprint 3, and E2B and the GitHub App in Sprint 0 (spike). Keys go into .env.local and Vercel env vars, never into chat or the repo.
